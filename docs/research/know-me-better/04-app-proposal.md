# 리서치 기반 AI Agent 앱 개선 제안

작성 2026-10-28 · 근거 `03-report.md` (학술 1,000편 · 반응 1,000건) · 대상 `docs/guided-agent-prd.md` 첫 버전

> **한 줄 요약.** "나보다 나를 아는 AI"로 가기 전에 "나를 잊지 않고, 무엇을 기억하는지 보여 주고, 확인받고 기억하는 AI"부터 만든다. 그다음 계정 연동 대신 **이 앱 안에서 실제로 한 일**을 근거로 나를 알아 간다.

---

## 1. 지금 앱이 사용자에 대해 아는 것

| 무엇 | 어디에 | 이 폰 모드 | 서버 모드 (웹 첫 버전의 주 경로) |
| --- | --- | --- | --- |
| 3문답 프로필 (하는 일·반복하는 일·기기) | `SettingsStore.profileSummary` → `buildSystemPrompt(userProfile:)` | 시스템 프롬프트에 들어감 | **안 들어감.** `TaskIn`은 `prompt`만 받고, `server/app/agent.py`의 `system_prompt()`에는 사용자 절이 없음 |
| 메일 말투 가이드 | `WritingStyleStore` (보안 저장소, 보기·고치기·지우기 화면 있음) | 들어감 | **안 들어감** |
| 지난 대화 | `ChatSession` + `ChatHistoryFiles` (대화별) | 같은 대화를 이어갈 때만 | 같은 작업을 이어갈 때만 |
| 대화를 넘나드는 기억 | 없음 | 없음 | 없음 |
| 홈 카드 순서 | `RecipeCatalog`가 3문답 `persona`로 정렬 | 말한 것 기준 | 말한 것 기준 |
| 내 것부터 넣기 (`/intake`) | 올린 내용만 보고 칩 3개 | 프로필 안 씀 | 프로필 안 씀 |

**진단.**
- 리서치에서 사람들의 1순위 불만은 "나를 잊는다"였습니다(반응 1,000건 중 28%). 범용 AI 앱 리뷰에서는 69%, 컴패니언 앱에서는 78%였습니다. 지금 구조라면 새 채팅마다, 그리고 서버 모드에서는 매번 처음 보는 사람처럼 대합니다.
- 반대로 잘한 점도 있습니다. 말투 가이드를 사용자가 직접 보고 고치고 지울 수 있다는 점은 연구와 맞습니다. 사용자들은 기억을 하나하나 보고 고치기를 원했고(R11, 119건), ChatGPT 메모리 연구에서는 96%가 사용자 모르게 만들어졌습니다. 이 방식을 모든 기억으로 넓히면 됩니다.

## 2. 리서치에서 나온 설계 원칙 6가지

| # | 원칙 | 근거 (`03-report.md`) |
| --- | --- | --- |
| 1 | **잊지 않는다.** 대화와 실행 위치(폰·서버)를 넘어 기억이 이어진다 | "나를 잊는다" 28%로 1위. 기억해 주면 "다시 설명 안 해도 돼서 편하다" 16%, 긍정 111건 |
| 2 | **몰래 기억하지 않는다.** AI가 제안하고 사람이 확인한 것만 저장한다 | ChatGPT 메모리 96%가 시스템 자동 생성(Dash 2026). 무엇이 기억됐는지 본 뒤 부정적 기대 위반(Chen 2026) |
| 3 | **기억을 쓸 땐 쓴다고 말한다.** 예고 없이 꺼내지 않는다 | 섬뜩함(16%)의 가장 흔한 계기는 예전 말이 갑자기 튀어나오는 것. "편하긴 한데 예전에 한 말이 갑자기 튀어나오면 섬뜩" (R0962) |
| 4 | **틀릴 바엔 묻는다.** 기억에 없으면 지어내지 않는다 | 잘못된 기억·추론 127건 중 99건 부정. "기억 못 한다 하면 될 것을 지어내서…" (R0296) |
| 5 | **편들지 말고 근거를 준다.** | 한국어 반응의 19%가 아첨 지적. 사람과 선호 모델 모두 아첨형 답을 더 좋게 평가하는 경향(Sharma 2024) |
| 6 | **말보다 행동으로 안다. 단, 해석은 본인이 한다.** | 자기보고는 실제 로그와 중간 정도만 일치(Parry 2021). 삶의 서사와 지금의 감정은 본인이 최종 판단자 |

여기에 이 앱의 사용자 특성이 하나 더 붙습니다. 타깃은 AI를 처음 쓰는 사람입니다. 사람처럼 대화하는 AI 앞에서 사람들은 더 민감한 이야기를 털어놓고, 잘못된 멘탈 모델 때문에 위험을 잘 알아채지 못합니다(Zhang 2024). 그래서 **기본값은 더 보수적**이어야 합니다.

## 3. 제안

### P0. 기억의 기본기 (첫 버전에 포함)

#### P0-1. 서버 모드에도 "나"를 넘긴다
- **무엇.** 작업을 만들 때 앱이 프로필 한 줄, 말투 가이드, 확인된 기억을 함께 보내고, 서버가 시스템 프롬프트의 `## 사용자` 절에 넣는다.
- **왜.** 웹 첫 버전의 주 경로에서 에이전트가 사용자에 대해 아무것도 모른다. 원칙 1.
- **어디.**
  - `server/app/main.py`: `TaskIn`에 `context: str | None` 추가, `create_task`와 `followup`에서 전달
  - `server/app/agent.py`: `system_prompt(now, user_context)`
  - `lib/remote/agent_server_client.dart`: `createTask(prompt, context)`
  - `server/app/intake.py`: `suggest()`에 프로필 한 줄을 넣어 칩을 사람에 맞춘다
- **설계 선택.** 기억의 원본은 **앱(사용자 기기)**에 두고 작업마다 보낸다. 서버에는 작업 기록 외에 사용자 기억을 따로 쌓지 않는다. 지우기와 끄기가 한곳에서 끝나야 원칙 2를 지킬 수 있다.

#### P0-2. 기억 장부 (`MemoryStore` + "AI가 기억하는 것" 화면)
- **무엇.** 지금의 프로필·말투 가이드를 포함해 모든 기억을 한 목록으로 보여 준다. 항목마다 고치기·지우기, 맨 위에 "기억 쓰지 않기" 스위치를 둔다.
- **왜.** 원칙 2. 사용자들이 가장 구체적으로 요구한 기능이다. "예전 방식은 기억 하나하나를 보고 고치고 지울 수 있었다. 새 방식은 덜 투명하다" (R0812)
- **어디.** `lib/memory/memory_store.dart` (신규, `WritingStyleStore`와 같은 보안 저장소 패턴), `lib/ui/memory_screen.dart` (신규). 진입점은 설정 화면의 "프로필 다시 설정" 자리와 작업 결과 카드.
- **항목 구조 (안).**

```json
{
  "id": "m_7f3a",
  "text": "근무표는 매주 월요일에 카톡 단체방에 올린다",
  "kind": "routine",            // fact | preference | routine | style | sensitive
  "scope": "work",              // all | work | personal
  "source": "task:2026-10-27 근무표 정리",
  "evidence": "\"월요일마다 이거 단톡에 올려요\"라고 말함",
  "createdAt": "2026-10-27",
  "confirmedAt": "2026-10-27",
  "lastUsedAt": "2026-10-28"
}
```

```
┌──────────────────────────────┐
│ AI가 기억하는 것 (7)       [끄기]│
├──────────────────────────────┤
│ 일   근무표는 매주 월요일에 단톡방에  │
│      올린다 · 10/27 작업에서       │
│      최근 사용 어제          [고치기]│
│ 일   카테고리는 식품·생활·전자 셋   │
│ 메일 인사는 "안녕하세요 OO님"으로    │
│ 개인 엄마 성경공부는 쉬운 말로 🔒    │  ← 민감 항목 표시
├──────────────────────────────┤
│ 오래돼서 확인이 필요해요 (1)        │
│      반복하는 일: 엑셀 정리 · 3달 전 │
│      [아직 맞아요] [지금은 아니에요]  │
└──────────────────────────────┘
```

#### P0-3. 기억은 "제안 → 확인" 후에만 저장
- **무엇.** 에이전트가 작업 중 기억할 만한 것을 `propose_memory(text, kind, scope, evidence)` 도구로 제안한다. 앱은 작업이 끝난 뒤 결과 아래에 **카드 한 장**으로 묻는다. 한 작업에 최대 1–2개, 칩 두 개로 답한다.
- **왜.** 원칙 2. PRD 4.2의 "질문 공세 금지"와도 맞춘다. 작업 중간에 묻지 않고, 끝난 뒤 선택 사항으로만 묻는다(단계 화면 3개 한도에 넣지 않음).
- **어디.** `lib/agent/agent_tools.dart`와 `server/app/tools.py`에 `propose_memory` 추가. `lib/ui/task_screen.dart`의 다음 할 일 카드(F7) 위에 기억 카드를 둔다.

```
┌──────────────────────────────┐
│ 다음에 다시 묻지 않게 기억할까요?   │
│ "카테고리는 식품·생활·전자 셋"      │
│ 왜: 이번 표에서 직접 정하셨어요      │
│      [기억해 두기]  [이번만]        │
└──────────────────────────────┘
```

#### P0-4. 확인 화면에 "참고한 기억" 한 줄
- **무엇.** "이렇게 시킬까요?" 화면의 조립 문장 아래에 이번 작업에서 쓸 기억을 보여 주고, 각각 ✕로 이번 작업에서만 뺄 수 있게 한다.
- **왜.** 원칙 3. 기억이 예고 없이 튀어나오는 대신, 실행 전에 미리 보인다. PRD H2(확인 화면 학습 효과)와도 맞물린다. 사용자는 "AI가 나에 대해 이걸 안다"를 확인 화면에서 자연스럽게 배운다.
- **어디.** `lib/ui/confirm_screen.dart`, `lib/agent/task_intake.dart`

```
이렇게 시킬까요?
"첨부한 엑셀의 '품목' 열을 보고 '카테고리' 열을 채워줘. …"

참고한 기억  카테고리는 식품·생활·전자 ✕ · 표는 카톡에 붙일 수 있게 ✕
[실행]  [고치기]  [복사]
```

#### P0-5. 시스템 프롬프트 규칙 (폰·서버 공통)
`lib/agent/prompts.dart`와 `server/app/agent.py`에 같은 절을 넣는다.

```
## 사용자에 대해 기억하는 것 (사용자가 확인함)
- [m_7f3a] 근무표는 매주 월요일에 카톡 단체방에 올린다 (10/27)
- …

## 기억 규칙
- 위 목록에 있는 것만 사실로 씁니다. 목록에 없는 개인 정보는 추측하지 말고, 필요하면 칩으로 묻습니다.
- 기억을 쓴 결정은 결과 보고에 "기억한 대로 ~했어요"라고 한 번 밝힙니다.
- 기억과 지금 요청이 다르면 지금 요청을 따르고, propose_memory 로 기억을 고칠지 제안합니다.
- 건강·종교·정치 성향·재정·성적 지향·가족 관계 같은 민감한 내용은 추론하지 않고 기억으로 제안하지도 않습니다. 사용자가 직접 기억해 달라고 할 때만 kind=sensitive 로 제안합니다.
- 평가·첨삭을 요청받으면 칭찬보다 고칠 점과 근거를 먼저 말합니다. 점수나 등급을 부풀리지 않습니다.
- 확신이 없으면 "모르겠어요" 또는 "이렇게 보이는데 맞나요?"라고 말합니다.
```

- **왜 민감 항목을 따로.** 좋아요만으로도 성적 지향(88%)과 정치 성향(85%)이 드러나고(Kosinski 2013), 성향에 맞춘 설득은 실제로 효과가 있습니다(Matz 2017). 개인정보보호법상 민감정보(사상·신념, 정치적 견해, 건강 등)와도 겹칩니다. 예를 들어 어머니 페르소나의 "성경 공부"는 종교 정보이므로 사용자가 직접 원할 때만 🔒 항목으로 저장합니다.
- **왜 첨삭 규칙.** 취업 준비 페르소나의 자기소개서 레시피에서 아첨은 실제 손해로 이어집니다. "상위 2–5%라는데 평가가 너무 후한 거 아니냐" (R0835)

### P1. 행동으로 나를 알아 가기

#### P1-1. 홈 순서를 "말한 것"에서 "한 것"으로
- **무엇.** 3문답 답(말한 것)으로 시작하고, 실제로 완료한 레시피·반복 주기·취소한 작업(한 것)이 쌓이면 갤러리 순서를 바꾼다. 차이가 크면 한 번만 부드럽게 알려 준다.
- **왜.** 원칙 6. 연구에서 AI가 본인을 이길 근거가 가장 탄탄한 영역이 "말과 행동의 차이"다(주간 사용 시간 오차 19.1시간). 다만 사람들은 이걸 '나를 안다'로 체감하지 못하므로(반응 4건), 지적하지 말고 **편해지는 쪽**으로 보여 준다.
- **예.** "처음엔 엑셀 정리를 자주 하신다고 하셨는데, 요즘은 메일 요약을 더 자주 하세요. 홈에서 메일 요약을 앞으로 둘까요?" [그렇게 해 줘] [그대로 둘게]
- **어디.** `lib/recipes/recipe_catalog.dart`의 정렬, 사용 기록은 `ChatSession`에 레시피 id를 남기면 충분하다(새 수집 없음).

#### P1-2. 인터뷰는 한 번에 몰지 말고 작업마다 하나씩
- **무엇.** 첫 실행 3문답은 그대로 둔다. 작업이 끝날 때 기억 카드 대신(둘 중 하나만) "다음엔 더 빨리 해 드리려고요" 질문 하나를 가끔 던진다. 칩으로 답하고 건너뛸 수 있다.
- **왜.** 2시간 인터뷰로 만든 에이전트가 본인 재응답의 85% 수준으로 그 사람을 재현했다(Park 2024). 인터뷰가 계정 연동보다 사람을 더 잘 알게 한다는 근거다. 하지만 이 앱의 사용자는 질문 공세에 이탈했다(PRD 4.2, AIdol 11명 중 6명). 두 근거를 합치면 **작업 끝에 하나씩, 열 번에 걸쳐 열 개**가 답이다.
- **질문 예 (레시피별로 카탈로그에 정의).**
  - 엑셀 정리 뒤: "이 표는 보통 누구에게 보내세요?" [사장님] [단톡방] [나만 봐요]
  - 메일 요약 뒤: "요약은 어느 정도가 좋으세요?" [한 줄] [세 줄] [자세히]
  - 성경 쉬운 말 뒤: "어떤 분들과 같이 보세요?" [혼자] [소그룹] [어르신들]
- **어디.** `server/app/tasks.json` 레시피에 `learn` 필드(질문·칩·저장할 kind), `lib/ui/task_screen.dart`.

#### P1-3. 오래된 기억은 다시 확인
- **무엇.** 90일 넘게 다시 확인하지 않은 기억, 또는 최근 요청과 어긋난 기억은 장부의 "확인이 필요해요"로 옮기고 프롬프트에서 뺀다. 말투 가이드도 90일이 지나면 다시 학습을 권한다.
- **왜.** 사람은 앞으로의 변화를 과소평가한다(Quoidbach 2013). 낡은 기억을 계속 꺼내는 것이 '잘못된 기억' 불만의 큰 몫이다.
- **어디.** `MemoryStore`의 `confirmedAt`, `WritingStyleStore.profile.updatedAt`

#### P1-4. 일과 개인 기억 칸막이
- **무엇.** 기억마다 `scope`(일·개인·공통)를 두고, 레시피가 어느 칸을 쓰는지 정한다. 근무표 작업에 가족 기억이 섞이지 않게 한다.
- **왜.** "일할 때 쓰고 싶은 기억과 개인 생활 기억은 다르다. 섞이지 않았으면 좋겠다" (R0946). 섬뜩함을 줄이는 가장 싼 방법이다.

### P2. 예측으로 증명하기

#### P2-1. 작은 예측과 적중률
- **무엇.** 반복 작업 알림(PRD F10)을 만들 때 "다음 주 월요일에도 근무표 정리하실 거죠? 그날 아침에 알려 드릴게요"처럼 **예측으로** 제안하고, 맞았는지 기록한다. 장부 맨 위에 "제가 맞힌 비율 8/10"을 보여 준다.
- **왜.** 연구가 "나보다 나를 안다"를 판단하는 기준은 예측 정확도 하나다. 과거 이력이 본인의 예측보다 다음 행동을 잘 맞혔다는 결과도 있다(자해 행동 예측 연구 2008, 일상 감정 예측 2024). '나를 안다'를 말이 아니라 숫자로 보여 줄 수 있다.

#### P2-2. "AI가 아는 나" 카드 (재미 요소, 바넘 방지)
- **무엇.** 한국에서 유행한 "나에 대해 아는 걸로 방 채워 줘" 같은 놀이를 앱 안에서 안전하게 한다. 단, **장부에 있는 사실만** 쓰고 성격 해석은 하지 않는다. 각 문장에 출처 기억 id를 단다.
- **왜.** 이런 놀이는 긍정 반응(감탄 R1·자기통찰 R10)이 많았지만, "감수성이 높지만 분석적" 같은 누구에게나 맞는 문장이 섞여 있었다(R0046). 초보자에게는 "AI가 나에 대해 이만큼 안다"를 확인하고 틀린 것을 고치게 하는 입구가 된다.

## 7. 결정이 필요한 것

1. **기억 원본 위치.** 이 문서는 앱(기기)에 두고 작업마다 서버로 보내는 안을 제안합니다. 웹 버전은 브라우저 저장소라 기기를 바꾸면 사라집니다. 가족 검증 단계에서는 괜찮지만, 이후 서버 동기화가 필요한지 정해야 합니다.
2. **기억 카드 빈도.** 매 작업마다 띄울지, 새로 알게 된 것이 있을 때만 띄울지. 이 문서는 "있을 때만, 최대 1–2개"를 제안합니다.
3. **민감 항목의 범위.** 종교(성경 공부)처럼 레시피 자체가 민감정보와 닿는 경우, 레시피 사용 기록 자체를 기억에서 빼야 하는지.
4. **이 폰 모드 유지 여부.** 웹 첫 버전이 서버 모드 중심이라면, 폰 모드 전용인 말투 학습(Gmail API)을 서버 경로에서 어떻게 쓸지(앱이 가이드를 보내는 방식이면 P0-1로 해결됩니다).
